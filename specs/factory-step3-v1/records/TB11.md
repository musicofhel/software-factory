## 1. Measured this row

- **CorvidLabs/attest 1.0.0 does not fit the note.** Its README (`gh api
  repos/CorvidLabs/attest/readme`, read only) describes a record `{reviewer, confidence, verdict,
  tests-passed, human-approved}` under `refs/notes/attest`, checked by `attest verify` against a
  confidence policy. It has no field for a gate verdict that CI can recompute (rails, scope,
  tamperguard, the gate command list). So the factory writes its own format, `factory-attest/1`,
  under `refs/notes/factory-attest`, and ADR-0007 decision 9 documents it and cites attest. An
  attest record can sit on the same commit later.
- **ubs stays out** (records/TB0.md (c): its license rider excludes Anthropic and anyone acting for
  it). The spec wants ubs **and** aislop for the job, so no `bugscan` job is added and no stub
  either. Q3 in HANDOFF names what is missing.
- **flaky-test-detective has no release** (records/TB0.md (c)). The JUnit-history classifier is step
  4; this row builds the quarantine expiry reader only.
- **`git clone` fetches no notes.** A CI checkout starts without `refs/notes/factory-attest`, so
  attest-verify fetches it from origin itself (tests/test_attest.sh case pass proves it on a fresh
  clone).

## 2. What was built

- **factory/bin/lib/attest.sh** (new): the note's format and its reader and checker.
  - attest_manifest: the note from the node's facts plus what git knows (tree, the base's
    `build-test.sh --list`, tests_run = that list when built and [] on a rebase strike). It refuses
    (exit 1, no note) a base whose store is not securityMode `unsigned-fallback`, because the note
    cannot be signed.
  - attest_read: exactly one JSON object, else 2.
  - attest_fetch: origin's ref into the same local ref; 2 when origin has none.
  - attest_target: the PR head; on merge_group and the first-party queue, the queue commit's second
    parent, which must be `[base, PR head]` and equal `gh api pulls/N .head.sha` (exit 2 otherwise,
    1 when gh fails).
  - attest_check: the shape first (every key of the format; fleet, hashes and verdicts objects),
    then the ticket open at the merge-base (named, never read as a rails fail), then the recompute:
    trailers, merge-base, head, tree, gate commands, tests_run, rails-proof and scope (dg_rails,
    dg_scope, each in its own subshell so a refusal inside is a `fail`), tamperguard on
    `mb...target` (dg_tamper_argv, I17), signing. One `mismatch:` line per difference.
- **factory/bin/attest-verify.sh**: the stub is now the checker. A desk, halt or human PR passes (no
  node built it; approvals gate it, TB10). A ticket PR needs jq and tamperguard, fetches the ref
  (not on the node), reads the note and checks it. Exit 0 pass, 2 missing note, mismatch or refused
  shape, 1 an operational error (gh, tamperguard, git).
- **factory/bin/run.sh and lib/run.sh**: gate_push writes `$LOGBASE.attest.json` after scope passes
  and before lock_check (action `attest-note`, or `attest-note-failed` → REASON attest-error,
  released). `run_push_attested` pushes the branch and the notes ref in ONE `git push --atomic`,
  leased on both. The notes ref grows from origin's tip, built on a per-slot scratch ref
  (`refs/notes/factory-run/slot-<n>`, deleted on every return). A lost race on the notes ref is
  retried from a fresh fetch, up to 3 tries; a branch that moved under its lease is not retried.
  PR_PENDING carries `attest {format, sha256}`. The PR body replaces "Gate-manifest hashes" with a
  rails-proof row and the line naming the note and its sha256. `run_gate_hashes` is gone.
- **factory/bin/flaky-check.sh** (new): reads `factory/policy/quarantine.json` (a desk file, I15).
  With `--base/--head` it reads the list that lands: the head's copy when BASE...HEAD changes it,
  else the base's. A desk PR renewing an expired entry would otherwise be red forever, and only a
  desk or human PR can change factory/policy/** (every ticket rails it; owners-check wants two
  owners). Each entry is `{test, issue > 0, expires YYYY-MM-DD}`, live through its expiry day (UTC,
  FACTORY_NOW). Exit 2 on an expired or malformed entry, 1 on a missing, empty or non-JSON list, or
  one without a `quarantined` array.
- **gates.yml**: attest-verify lost its `needs:` (a required job skipped by a failed need reports
  success, records/TB0.md (b)). It gained setup-python 3.14 and `pipx install tamperguard==0.2.0`,
  the tamper job's pins. There is a new `flaky` job, run from ./.base (I16). The header now says no
  w:heavy job is required until a self-hosted factory-node runner exists (ci:G14), that there is no
  bug-scan job and why, and that skills-scan is not required.
- **skills-scan.sh / skills-janitor.yml** (merge:G18): the stub still exits 2. The reason is in both
  headers: its body is an agent's verdict (the /janitor-security review), not a deterministic gate a
  hosted runner recomputes. It is required only once it has a real body and runs on both paths (I18).
  The workflow has no merge_group and is not in the desk note's required set.
- **join.sh**: the token's `ref_patterns` gains `refs/notes/factory-attest`.
- **docs/adr/0007-merge-queue.md**: decision 9 (the note, its check, attest 1.0.0 cited) and a
  consequence (a PR built before the note existed fails attest-verify until rebuilt; notes
  accumulate on one ref).
- **The desk note** `tests/sim/desk/factory/policy/branch-protection.json` requires `flaky` (14
  contexts). `apply-branch-protection.sh --check --policy <the desk note>` passes.

## 4. Deviations and decisions

- **Scope deviations.** Dogfood on the T30 commit (`--ticket T30 --base <c>~1 --head <c>`, fake gh
  on PATH): commit-check pass (1 commit carries the trailers), rails-proof pass (no rail of T30),
  scope-check exit 2 naming exactly two paths: `tests/test_gate_context.sh` (its attest-verify
  stub case became the attest-verify context case, and flaky joined its base-script job list) and
  this record. The TB11 static checks that HANDOFF had planned for test_halt_rules.sh and
  test_diff_gates.sh went into test_attest.sh's gates-yml case instead, which is in scope.
- **The quarantine list read from the head when the PR changes it** (§2). The base's script reads
  it (I16), so the head supplies data, never code, and only under two owners' review.
- **attest-verify has no `needs:`.** Run on its own it reports its own verdict on every path. Its
  recompute of rails, scope and tamperguard repeats those jobs' work (about one tamperguard call
  more per PR). The sim's i17 judge compares the de-duplicated argv set (`sort -u`), since both jobs
  call tamperguard with the same argv.
- **What the note does not prove.** CI cannot recompute fleet's run id, strike count or the two
  hashes. They are a record. That fleet ran the gate commands is the node's claim; CI's build-test
  job runs them again.
- **The node refuses to write a note a signing store would reject** (attest_manifest, fix 5 above):
  the run ends attest-error, released, instead of pushing a PR that attest-verify must fail.
