## 1. Measured this row

- **Check-run names and the app id** come from records/TB0.md (b): a check run is named by its bare
  job id, and the GitHub Actions app id is 15368. A called workflow's jobs are named
  `<caller> / <job>` (TB9's serial queue: `gates / <job>`), so the required contexts are the bare ids,
  and the serial queue's land acts on `needs.gates.result`, not on required checks.
- **GitHub's merge queue is org-only** (records/TB0.md (a)). apply-branch-protection.sh reads
  `GET repos/<repo> .owner.type` and sends the ruleset's `merge_queue` rule only for `Organization`.
- **GitHub cannot count two code owners.** Ruleset `pull_request.require_code_owner_review` counts
  one owner per path, and the `required_reviewers` rule needs a Team. A user-owned repo has no Teams.
  So the two-owner rule is a first-party required check (`owners`), and the HALT rule is another
  (`halt-guard`). Both are listed under the policy's `unexpressed`.
- **GitHub re-runs no check on a review.** A review changes what `owners` and `halt-guard` count, so
  reviews.yml re-runs those two jobs (`POST actions/jobs/<id>/rerun`). Whether a re-run requested with
  GITHUB_TOKEN starts the job is not documented: a kit line for TB12.
- **Environments:** `PUT repos/<r>/environments/main` with `deployment_branch_policy
  {protected_branches: false, custom_branch_policies: true}`, then `POST
  .../deployment-branch-policies {name: main, type: branch}`. Only a job running on `main` can read
  that environment's secrets. A `pull_request` run has a `refs/pull/N/merge` ref and is refused.
  `pull_request_target` runs on the base ref (`refs/heads/main`), which is why halt.yml checks out
  main only and reads nothing from the PR but the label.
- **Pins:** every `uses:` resolved to the commit its tag points at, today, with `# vX.Y.Z` on the
  line (test_halt_rules workflows-static). actionlint 1.7.12, linux amd64 tarball, sha256 pinned in
  join.sh (ACTIONLINT_PIN). CI installs `actionlint-py==1.7.12.24` (the same binary, through pip).

## 2. What was built

- **The policy, as a desk note (I15).** `tests/sim/desk/factory/policy/branch-protection.json`
  replaces `factory/policy/branch-protection.json` in a desk commit:
  - `protection: null`. Ruleset `main`: deletion, non_fast_forward, pull_request (0 approvals,
    code-owner review, dismiss stale, `require_last_push_approval`, merge only);
  - required_status_checks (strict): the 13 bare job ids of gates.yml (context, build-test,
    rails-proof, scope, tamper, dependencies, commit-check, depends-on, tier-order, desk,
    attest-verify, owners, halt-guard), each `integration_id: 15368`;
  - merge_queue (MERGE, one entry built and merged at a time), sent only on an Organization repo;
  - `unexpressed`: the HALT rule, the two-owner rule, and "only the App merges a ticket PR" (§4).
- **`apply-branch-protection.sh`:**
  - `--check` (I18, offline, yq): the required set equals the gates.yml jobs that report on both
    paths (pull_request, merge_group and workflow_call, with no job-level `if:`). Each is
    `integration_id` 15368. A required job's `needs` are required too.
  - The merge_queue rule is sent only on an Organization repo. Elsewhere it is printed as skipped.
  - `--bootstrap [--apply]` creates the `nodes` and `flaky-history` branches (one-commit orphans
    holding a README) and environment `main` restricted to branch main. What exists is a noop.
    bs_send keeps its results in a file, because a subshell lost them.
- **`factory/bin/owners-check.sh`** (gates.yml job `owners`, run from ./.base, I16): a PR whose
  BASE...HEAD touches `factory/**`, `.adlc/**`, `.github/**`, `.claude/**` or a CODEOWNERS file passes
  only with two distinct approvals by that path's owners. The owners are the last matching line of the
  base's CODEOWNERS, in GitHub's lookup order. An approval counts when it is the reviewer's latest
  decisive review and was given on the current head (require_last_push_approval). The author never
  counts. Team and e-mail owners are named as uncountable. On the queue path the head is read from
  GitHub. `--only <path>` (for halt-guard). `--rerun` (reviews.yml). An unreadable CODEOWNERS or
  review list fails closed (exit 1).
- **`factory/bin/halt-guard.sh`** (gates.yml job `halt-guard`):
  - check mode: a PR that deletes `factory/HALT` passes only with two distinct code-owner approvals
    on its head (`owners-check.sh --only factory/HALT`). Adding or editing HALT passes, and so does a
    PR that does not touch it.
  - `--add --actor <login> --reason <text> [--apply|--dry-run]` (halt.yml): the actor needs write
    permission (`GET collaborators/<login>/permission`). The script commits `factory/HALT` onto the
    tip of main as `github-actions[bot]` and pushes it. It retries only when main moved, and any
    other refusal dies, naming git's error. A main that already holds HALT is a noop.
- **Workflows:**
  - `halt.yml` (new): dispatch, or the `factory:halt` label on an Issue or a PR
    (pull_request_target, main checked out). It mints the App token and runs halt-guard `--add`.

  - `reviews.yml` (new): on a submitted or dismissed review, `owners-check.sh --rerun` from the base.

  - Every action is pinned by sha with its tag in a comment.
  - `environment: main` on the 7 App-key jobs: post-merge, enqueue pick, land and dequeued,
    janitor, labeler, halt.
- **`janitor.sh`:** a missing `nodes` branch reads as empty (NODES_ABSENT). A successful `--apply`
  creates it as a parentless commit holding janitor/state.json. An unreachable remote still fails.
- **`join.sh`:**

  - the env file's `GH_TOKEN` line reads `$FH/token` when it is sourced, so gh and git run as the
    node;

  - the actionlint in-plane refusal (pin 1.7.12 and its sha256).
- **`Makefile`:** `make lint` fails when actionlint is missing (carry 8: it never skips silently).
- **`docs/adr/0004`:** amendment, C and D built.
- **Fakes and sim:**
  - `tests/fakes/gh`: environments routes. `tests/fakes/join/multi`: the fake uv accepts `--python`.
  - Driver: `uses:` `@<anything>`, `environment:` checked against SIM_ENVIRONMENTS, the

## 4. Deviations and decisions

- **I1 incident (session 25).** One `apply-branch-protection.sh --bootstrap --apply` smoke run used
  the REAL gh, because PATH lacked tests/fakes. It sent 4 POST/PUT calls to `repos/a/b/...` on
  github.com, a repo that does not exist or is not ours. All four answered 404, so nothing was
  written. Since then every smoke run goes through the fakes (gotcha 26).
- **Direct merges are not disallowed** (the spec: "otherwise the policy requires the first-party
  queue's check and disallows direct merges by everyone but the App"). A ruleset rule cannot be
  scoped to a PR class. Restricting updates of main to the App (rule `update`) would also strand the
  desk, human and HALT-removal PRs, which enqueue.sh does not land. The policy requires the same
  gates the queue runs, strict (up to date with main), and lists the rule under `unexpressed`.
  Non-blocking Q2 in HANDOFF.
- **The App-key environment** covers post-merge, enqueue (pick, land, dequeued), janitor, labeler
  and halt. mirror.yml reads no key, so it has no `environment:`. No revoke workflow exists. Both
  differ from the spec's list.
- **A dispatch has nothing to label** with `factory:halt`. Only the label path leaves the label
  behind; a dispatch writes the reason into factory/HALT.
- **Who may approve:** owners-check counts code owners only. tier-order and enqueue still count any
  APPROVED review (they only make PRs wait, so they fail safe). Narrowing them to
  OWNER/MEMBER/COLLABORATOR is outside T29's scope: carried.
- **CODEOWNERS** (outside T29's scope) still describes the HALT interim and names one owner. The desk
  updates it with the second owner. Until then no PR touching the factory's own paths can merge

- **tamperguard.toml (ci:G20)** is mentioned in `factory/policy/README.md:16` but does not exist.
  That file is under `factory/policy/**`, so the fix is a desk note: drop the row.
