**The base ref.** `--base origin/main` does resolve in a merge_group checkout, because fetch-depth 0 fetches every head. But it is main at job time, not `merge_group.base_sha`. In the sim, a post-merge push after the group was created made the two-dot `git diff origin/main` report `factory/ledger/post-merge.json` as a PR change, which would be a false scope failure. Three-dot, or the explicit `base_sha`/`head_sha` pair, gave exactly the two PR files. post-merge pushes after every merge (post-merge.yml:12-18), so this race is routine.

**`github.event.pull_request` on merge_group.** It is empty, and so is `github.head_ref`. Today only the concurrency key reads it (:10), and that falls back to `github.ref` safely. Any real body that takes the ticket id from `pull_request.head.ref`, the base from `pull_request.base.sha`, the tier from `labels`, or `number`/`body`/reviews (for halt-guard and depends-on) gets "" in the queue. The id must come from `merge_group.head_ref` (`gh-readonly-queue/main/pr-<N>-<sha>`) → `gh api pulls/N`, or from the `Ticket:` trailer on `head_sha^2`. The base must come from `merge_group.base_sha`.

**Which data is trusted.** Rails, scope, edges and the fleet gate commands come from the **base** store (`base.sha` / `merge_group.base_sha`), never from the PR head. adlc's own CI gate does exactly this: rails-guard-ci reads the "trusted" base config (rails-guard/lib/ci/rail-freeze.mjs:208). In the sim it refused with `acknowledgedNewRailBypass must already be set on the base branch`, rc 1. The gate scripts also run from the PR checkout today, so a PR whose scope includes factory/bin can rewrite scope-check.sh.

**apply-branch-protection cross-check.**
- merge_group trigger: present (:8).
- Merge queue: MERGE, build 1, merge 1, ALLGREEN, timeout 60 (branch-protection.json:43-54). OK.
- bypass_actors: [] except the App (:13, apply script :202-204). OK.
- Rejected: `required_approving_review_count: 1` (:21), where the spec wants two humans (L795-797). CODEOWNERS has one owner (CODEOWNERS:3-8).
- **Required contexts `gates / <job>` (:33-39) never match.** A check-run's name is the job name: this repo's own runs are named `janitor`, `mirror`, `digest`, and actions/checkout's are `Analyze (javascript)`, with no workflow prefix. tests/test_halt_rules.sh:94 asserts the wrong strings.
