## 3. main's `.adlc/config.json` fleet block (for a real ticket on main)

Shape derived from tests/live/test_smoke_live.sh:85-90, which uses `.fleet = {gate: {test}, allowedCommands}`.
Each allowedCommands entry becomes `Bash(<entry>)` in the worker's settings. The repo-settable keys
(@adlc/fleet lib/config.mjs:209-245) are gate, init, allowedCommands, concurrency, base, timeoutMinutes,
prosecuteFailOn, review*, adapterStdin. Adapter, model and modelAuthKey are CLI-only and warned/ignored
if set here. Ruling Q3: one repo-wide block with gate commands plus a desk-written allowedCommands list.

```json
{
  "version": 1,
  "securityMode": "unsigned-fallback",
  "harnesses": { "claude-code": { "railEnforcement": "auto" } },
  "fleet": {
    "gate": { "test": "make test", "build": "make lint" },
    "allowedCommands": ["make test", "make lint", "bash tests/*.sh:*", "./factory/test.sh", "shellcheck:*"],
    "prosecuteFailOn": "medium",
    "timeoutMinutes": 30
  }
}
```

Caveats, all speculative until a live run:
- (a) `make lint` falls back to `uvx` downloads (Makefile:18-25), which build.toml's no-network profile
  denies. Nodes therefore need system shellcheck (join probe), or `build` stays CI-only.
- (b) The spec says CI "Build + test" runs **the project's fleet.gate commands**, but gates.yml:24-27
  hard-codes `make test`/`make lint`. build-test should read `fleet.gate` from origin/main's config, never
  the PR tree, so one source serves node and CI.
- (c) .adlc/** is CODEOWNERS-protected and only main writes it. The scope gate must refuse any ticket PR
  that touches `.adlc/**`, including this config.
- (d) prosecuteFailOn and the strike defaults are in the spec's two-approval set (SPEC L797-800).
