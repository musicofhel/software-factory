# Intake segment simulation: T20 (tier:1, Depends-on T21), read-only, origin/main 4ea237c

Sandbox: a copy of the repo at `scratchpad/sim/intake/repo` with origin removed. Real `@adlc/cli` 1.12.0 ran against the copy's store, and the fake `gh` came from `tests/fakes/lib.sh`. Two scripts drove it: `sim-mirror.sh` (real adlc) and `sim-mirror2.sh` (fake adlc plus the real forecast). Nothing was written to ~/software-factory, its store, ~/.factory or GitHub; the only GitHub calls were read-only API calls.

Tickets used:
- T21 is the parent: open, tier 0, rails `factory/policy/**`.
- T20 is the child: tier 1, rails `factory/policy/**`, and scope `factory/bin/merge-guard.sh`, `tests/test_merge_guard.sh` and the deliberately wrong glob `factory/nosuchdir/**`.
- The dependency is an edge `{to:"T20"}` on T21.

### Confirmed working
- The ticket-check rails rule.
- Mirror create/update/close, the ADR-0002 header parse to `w:`/`tier:` labels, the `Depends-on:` and `Ticket-Hash:` body lines, and the dependency hold through the forecast waves.
- Post-merge's own mirror job, which sidesteps the GITHUB_TOKEN push rule (post-merge.yml L70-85).
- summon.sh ticket and link extraction from a mirror Issue.
- The claim.sh filter and its weight cap.
- version-check pins.

### Speculative, flagged
- I5: the remedy (manifest.d segments).
- I8: the GITHUB_TOKEN event rule as it applies to this repo.
- GitHub's native merge queue has no label-priority ordering, so "tier:0 before tier:1" in SPEC L671 needs the guard (or a dispatcher) to control *enqueue* order, not just hold. Not verified against current GitHub docs.
