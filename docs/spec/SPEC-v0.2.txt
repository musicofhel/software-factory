  Purpose and constraints
  A hobby team pools its own laptops and model subscriptions to build one project from a
  shared ticket backlog. Agents do the building; humans hold two gates. This is the final
  consolidated spec: the working draft (v0.1 through the supersession pass) is kept as the
  record of how each decision was reached, and this document states only what is decided.

  Built from ADLC (lifecycle doctrine, gates, fleet ), a subset of ACFS (box bootstrap,
  safety hooks, capacity probe), and the best-in-slot tools the supersession pass found.
  Where a borrowed tool and a first-party component overlap, the borrowed tool wins
  unless this spec says otherwise.

  Non-negotiables

        Cheap: one public GitHub repo, free Actions minutes, self-hosted runners on
        members' machines for heavy jobs, no paid service, no shared API key.
        Pull, not push: idle nodes claim work. No scheduler, no coordinator process, no machine
        that must stay on. Every cross-node service is a GitHub Action or a git branch.
        Heterogeneous nodes: any Linux, macOS or WSL2 box with 8 GB+ RAM and one
        authenticated coding-agent CLI can join.
        Control flow is code, judgment is models (ADLC D0). No model decides a claim, a gate
        verdict, a merge order, or a release.
        Two human gates only: spec approval (P1) and behavioral acceptance (P6). Everything
        between is machine-gated.
        Etiquette by mechanism, not instruction: branch protection, claim TTLs, scoped
        tokens, a kill switch, quota caps. Nothing that matters lives only in AGENTS.md .
        The factory must never leave a member unable to use their own account. Quota cap
        defaults to 40% of the owner's window and the node sleeps through the owner's
        working day.

  Out of scope: Windows outside WSL2, private repos, cross-project sharing, money
  changing hands, agent-to-agent messaging (ADLC rejects it; conclusions pass through
  artifacts).

  Decisions baked in

        Ticket source of truth is .adlc/tickets.json , mirrored to GitHub Issues for display
        and human interaction. The lock is a git ref, not the Issue (Claim protocol). Beads is
        dropped to avoid two ledgers; tk is the trial replacement if tickets.json becomes
        painful.
        ACFS supplies the bootstrap, dcg and the capacity probe only. Agent Mail and NTM
        are not used.
        Everything a node needs is in the repo. Fresh clone plus /factory:join is the whole
        onboarding.
        The project license is chosen in PROJECT.md before the first merge. Node owners
        DCO-sign agent commits through the commit trailer, and every agent commit carries
        an Assisted-by: trailer so the project's own AI-contribution disclosure is machine-
        checkable.
        The factory's first project is the factory: every factory/ change goes through the full
        lifecycle before the queue opens to the real project.

  Join wizard
  A node is any box that has run /factory:join , a Claude Code skill in
   factory/skills/join/ that probes the machine, installs the toolchain in safe mode, and
  commits a manifest. It writes nowhere outside the clone and ~/.factory/ .

    1. Probe: nproc , total and free RAM, free disk, OS, which of claude , codex , agy ,
         opencode are installed and authenticated. Timed dry run of the project's full suite sets
         heavy_gates .
    2. Install, pinned: @adlc/cli and the ADLC plugin; vetto (sandbox); Ralon (rails path
        lock); dcg (destructive-command hook; Vallum instead when the node runs Cursor
        or Gemini CLI); tamperguard ; cux for account rotation; adlc init if .adlc/ is
        missing. Refuses to proceed if --dangerously-skip-permissions is aliased in the
        shell. Never vibe mode.
    3. Register: fine-grained GitHub token scoped to this repo (contents: write on
         ticket/** , nodes/** and refs/locks/** only, 90-day expiry); register the box as a
        self-hosted Actions runner with label factory-node in a runner group scoped to this
        repo.
    4. Commit <handle>.json to the nodes branch and push. That push is the first
       heartbeat.
    5. Print the run-loop command and RULES.md .


  Manifest
   nodes/<handle>.json : handle , owner , os , cpu , ram_gb , slots , heavy_gates ,
   adapters (name → pinned version), quota_tier , quota_cap , quiet_hours , accounts
  (count only, for cux), factory_version , last_seen , status .

         slots = floor(free RAM GB / 2) − 1, capped at 8; this is the fleet concurrency the node
        runs with.
         heavy_gates is true if the full suite finished inside the ticket timeout in the wizard's
        dry run.
         quota_tier is self-declared and used only to pick ticket weight; nobody audits it.

         quota_cap defaults to 0.4 of the owner's quota window. The governor pauses the
        node at the cap.
         quiet_hours defaults to the owner's working day in their time zone; the node does not
        claim inside them.

  Run loop
  One loop per slot. /factory:run starts it; it is a shell script, not an agent.

     loop:
       version_check        # factory/VERSION and adapter pins; behind → pull,
     restart, or refuse to claim
       heartbeat            # last_seen into nodes/<handle>.json on the nodes
     branch, push (hourly at most)
       kill_switch_check                           # factory/HALT present on origin/main → sleep 30m,
     continue
         quiet_hours_check                         # inside owner's quiet hours → sleep until they end
         quota_check                               # cux status; all accounts ≥ quota_cap of window →
     sleep until reset
       claim                                       # git-ref lock protocol; nothing claimable → sleep
     10m, continue
       git fetch
       if ticket/<id>/* exists from a lapsed claim: worktree from it, append its
     dead-end material to the ticket
         else: git worktree add .worktrees/<id> origin/main
         ralon run --lock .ralon/<id>.lock -- \
         vetto --profile factory/policy/build.toml -- \
           fleet run --tickets <id> --concurrency 1 --no-pr --no-complete \
                  --adapter <preferred adapter> --worker-deps <lockfile cache> \
                  --max-strikes <budget.strikes> --wall-clock-minutes <budget.minutes> \
             --pre-strike-argv '["cux","status","--json"]' --json
         case reason:
         merged into fleet/run-*     → tamperguard + scope check locally; push
     ticket/<id>/<handle>; open PR; comment on Issue
         quota-paused | wall-clock                         → keep lock (heartbeat it), push partial
     branch, sleep, resume
              strikes-exhausted | flail                    → push branch, label Issue needs-desk, delete
     lock
              review-unavailable                           → delete lock, sleep 30m
              anything else                                → delete lock, comment reason, continue
         git worktree remove .worktrees/<id>

  Two sandbox profiles in factory/policy/ : build.toml denies all network and bounds
  writes to the worktree and the dependency cache; agent.toml allows egress only to the
  adapter's API domain. fleet's strike runs under build.toml for test and build steps and
   agent.toml for the model turns; vetto is fail-closed, so a profile that cannot be applied
  stops the strike rather than running open.

  Transcripts never leave the node. The ledger and PR body carry gate-manifest hashes,
  reason codes, strikes, adapter names and token counts; never prompts, file contents or
  session text. cass indexes sessions locally for the node owner only; deja-vu is the drop-
  in if cass is unavailable on a platform.

  Gates before a ticket is claimable: spec-lint clean; coldstart gap list empty; merge-
  forecast certifies it against every other open ticket at the current width (file overlap,
  import-graph radius, co-change coupling); contract lint passes (scope globs resolve, tier
  set, no self-review possible). A ticket failing any of these is labeled needs-desk and is
  invisible to nodes.


  Intake and the desk
  The desk is a rotating weekly duty, not a role. One person per week; that week they do not
  run a node. The intake agent drafts tickets (scope, weight, tier, acceptance criteria with
  verification methods) from PROJECT.md and the backlog, scoring each request by risk ×
  blast radius (tree-sitter reverse traversal from the touched symbols, the perla method).
  Low risk, small radius, cites the charter: the draft goes straight to spec-lint and the desk
  sees it in the digest. Anything else waits for the desk.

  Intake rejects, and the desk does not rescue, any ticket that cannot cite the PROJECT.md
  line it serves. Refactors, dedup passes and test additions pass cold-start cleanly, and a
  project made only of those gets cleaner and does not move.

  Desk disagreements are ADRs in docs/adr/ through adrs ; the desk rotation has an odd
  number of people.


  Claim protocol
  The lock is a git ref, not the Issue assignee. Creating a ref through the GitHub API fails
  with 422 if the ref exists, which makes it the only true compare-and-swap GitHub offers
  without a server. The assignee field is set after the lock for humans to read; it decides
  nothing.

    1. Node lists Issues labeled ready and w:<weight> where weight ≤ its capacity, oldest
        first, skipping any whose lock ref exists.
    2. Node runs POST /repos/{r}/git/refs with ref: refs/locks/issue-<n> and sha =
        a commit on the nodes branch carrying {handle, run_id, slots, claimed_at} . On
        422 or any error it moves to the next Issue. No retries on the same Issue.

Distributed Software Factory — Spec v0.2 (final)




    3. On success: gh issue edit <n> --add-assignee @me --add-label in-progress ,
        and one comment: handle, fleet run id, slot count, expected finish. This is the only
        comment a node writes until it has a result.
    4. Heartbeat: every hour the node force-updates the lock ref to a new commit with a
        fresh claimed_at . A lock whose commit is older than 24 h is stale.
    5. Release: the node deletes the ref. The janitor deletes stale refs, and any ref whose
       node is stale , and any ref beyond a node's slots (newest first). A stale lock with a
        pushed ticket/<id>/* branch newer than the TTL is left alone; one without a PR after
        48 h is released and the branch kept for the next claimant.

  No node ever deletes a lock it does not hold. No node ever edits labels other than adding
  in-progress to its own claim. Labels are set only by write access, so nothing a stranger
  files becomes claimable without the desk.


  Rails and build gates
  Rails are what the builder cannot argue with: tests, contracts and a tool policy written
  before any implementation exists, by an agent that will never see one, then frozen at the
  operating-system level for the length of the build.


  Rail author
  Owns specified → railed. Reads the approved spec in a fresh context; writes failing tests,
  type stubs and contract tests for every DAG edge; emits .agents/permissions.json
  (agent-perms: deny-first tool rules, sandbox.writableRoots = the ticket scope,
   network.domains = none); declares the rail paths in the ticket; runs the suite and
  confirms it is red for the right reasons ("not implemented", never "test broken"); hands off.
  Frontier-tier, one ticket per context. Must not see the builder's branch, write
  implementation, gate on coverage percentage, or edit rails after the freeze. Done when
   hollow-test finds no surviving mutants in the rails.

  qikly's withholding check is borrowed as the enforcement: a CI step fails the rail PR if any
  rail file's content appears in the spec text handed to the builder, so acceptance criteria
  cannot leak implementation hints.

  Freeze
        Ralon: the run loop launches fleet under ralon run with a per-ticket agent.lock
        listing the rail paths. Writes are denied by the kernel (Landlock on Linux, Seatbelt on
        macOS), not by a hook the agent could route around.
        Proof: CI runs git diff --quiet origin/main -- <rail paths> on every PR. A non-
        empty diff fails the gate.
        Tamper check: tamperguard scores the diff for new skip/xfail/ .only markers, deleted
        or loosened assertions, lowered coverage thresholds, whole-file suppressions and
        config loosening; exit 2 fails the gate. It runs on the node before push and again in CI.

  Three details that break early if left implicit:

        Dependencies. The build profile denies network, so npm install fails on every strike.
        Each node keeps a lockfile-keyed dependency cache and passes it with --worker-
        deps ; CI uses the setup-action caches. Adding or upgrading a dependency is a desk
        ticket, never a builder decision. A Nix-based project sidesteps this entirely and is the
        recommendation for any new project started on the factory.
        Flaky tests. A flaky rail is a rail that lies, and fix-back will chase it forever. A failure
        classified as flaky does not fail the gate but opens a needs-desk ticket naming the
        test; the test stays quarantined until the desk fixes or deletes it, and quarantine
        entries carry an expiry date.
        Flail. LoopGuard tails the adapter's session log and pauses a strike that repeats the
        same tool call or error, or exceeds the ticket's token budget; unasked classifies out-of-
        scope edits as drift. The run loop treats either signal as a flail reason: push the
        branch, write the dead-end material to the Issue, release the lock.


  Prosecution, verification, merge, acceptance, release
  Prosecution is two pods, not one. Prosecutors produce findings; a separate verifier in a
  fresh context reproduces each one and kills the rest. Only confirmed findings spawn fix
  tickets.

  Prosecution
  Runs on the node with the node owner's quota, through the packaged adversarial-
  review CLI ( --providers across model families, --quorum , --loop until no gating
  findings, exit codes derived from severity × confidence, never from a model's verdict).
  The run loop prefers an adapter the builder did not use when the manifest lists one, and
  the PR body records which adapter prosecuted so calibration can measure the
  difference. adversarial-review must be on PATH or the loop refuses to start.
  Prosecution depth ( prosecuteFailOn , quorum size, loop cap) lives in factory/policy/
  under CODEOWNERS.

  A sampled 1-in-5 re-prosecution runs in CI on a volunteer factory-node runner with a
  different adapter; it never blocks, it feeds calibration.


  Verifier
  Owns prosecuting → verified. Wraps Sauron: every finding becomes a claim with an
  evidence locator; mechanical checks run first (does the file, line and symbol exist; does
  the test the finding names fail), semantic faithfulness only for what survives. Two rules
  from ASImposium are hard: REVIEWER_IS_AUTHOR is a refusal, and dispositions are
  computed from reviews, never author-set. Confirmed findings become fix tickets that
  enter at building with the parent's rails appended; the parent waits in verified until its fix
  tickets are integrated. Where a finding is reproducible as a test, edgeverdict 's pattern
  applies: the verifier ships the failing test with the fix ticket.


  Calibration
  Monthly, on a volunteer runner: ReviewBench (219 real PRs with golden findings, local
  judge, per-category recall and precision) plus the Qodo planted-bug set. Recall below
  threshold in a category adds a lens to the prosecution charter through the normal
   touches_factory PR path. Nothing plants bugs into the project's own diffs yet; that stays
  a first-party extension.


  Merge
  GitHub's merge queue, sequential. Order is foundation-first (ADLC D2): tier:0 before
  tier:1 before tier:2 , first-done-first within a tier, enforced by a small Action that
  holds a PR out of the queue while any Depends-on: parent is unmerged (the MergeGuard
  pattern, first-party because the product is SaaS). Ejection on conflict is a transition,

  queued → building, with a rebase strike that does not count against the ticket's budget;
  the builder cherry-picks onto a fresh branch from main , never rebases. autorebase
  labels the conflict so the digest can show it.

  Ticket completion ( adlc ticket complete --write ) happens in a post-merge CI job,
  never on a node, so .adlc/tickets.json is only written from main .


  Preview and acceptance
  Each integration branch gets a Docker Compose deployment on the heavy node with the
  most free slots, an address under a wildcard subdomain, and a TTL in the branch's deploy
  record; the janitor tears it down at TTL or on PR close. behavior-diff runs the project's
  probes against the preview and the current main deployment and writes a short report
  into the PR: routes, API responses, CLI output, DB state. momus is the HTTP half if the
  first-party probe runner proves thin.

  Acceptance is the second human gate. The summoner pings one named human with the
  report and the address. Auto-accept when the behavior diff is empty and
   touches_factory is false; touches_factory tickets never auto-accept.


  Release
   dsr on the heavy node: multi-host build over SSH where the project needs more than one
  platform, minisign signing, SBOM, SLSA provenance, Docker canary of the installer. Trigger
  is accepted → released; the host list is read from node manifests with heavy_gates:
  true . When CI minutes allow, the same job runs as an Action; dsr exists so a throttled
  month does not stop releases.


  Humans in the loop
  Humans touch the factory in four places: the two gates, the weekly desk, and the kill
  switch. Everything else is designed so a human can go a week without opening the repo
  and still be pulled in within an hour of being needed.


  Summoner
  Code, not an agent: an Action triggered by hub events, posting to a Discord webhook (or
  email) the human already reads. Exactly two kinds of immediate message, each to one
  named human with the ticket id, the decision needed and a link:

        Gate ask: spec approval (P1) or acceptance (P6).

        Halt notice: kill switch set, or a node retired with open claims.

  Everything else (needs-desk, quota pauses, retirements, drills, merges, ejections, flaky
  quarantines) goes into one daily digest, a scheduled workflow that is silent when there is
  nothing to report. The summoner never polls humans, never messages agents, never
  decides anything.

  When the gate needs a recorded decision rather than a ping, trstringer/manual-
  approval is the serverless fallback: it opens an Issue assigned to the approvers and
  parses approve/deny comments. awaithumans in server mode is the upgrade if humans
  start colliding on approvals and typed responses are needed; it runs on a volunteer node
  and is not required.


  Desk duty
  One person per week, odd-numbered rotation. That week they approve or reject intake's
  drafts, resolve dead letters (needs-desk → specified or abandoned), own hotfixes and
  reverts, and read the digest. They do not run a node. The desk is where the week-one
  failure lives (ready queue at zero because writing cold-start-clean tickets is
  unglamorous), so intake drafts everything and the desk never starts from a blank page.


  Kill switch
  A file, factory/HALT , on main . Every run loop checks for it before claiming; present
  means sleep 30 minutes and check again. Anyone with write access can add it with a one-
  line PR that bypasses nothing but needs no review (the CODEOWNERS rule for
   factory/HALT requires two approvals to remove, zero to add, which the branch rules
  express as a required-reviewers rule keyed on deletion). The halt also sets the
   factory:halt label so the summoner fires a halt notice.

  Removing it is the two-person rule. slb is the intended tool ( slb run blocks until a peer
  approves, SHA-bound, logged), but its README currently states that independent-
  reviewer auth is not implemented and peer approvals fail closed. Until the monthly drill
  shows slb clearing a halt with two real approvers, the two-person rule is the
  CODEOWNERS two-approval requirement on the deletion PR and nothing else.


  Drills
  Once a month the janitor opens a drill ticket that trips the kill switch, retires a test
  node with an open claim, forces a merge-queue ejection, and lets a preview expire. Each
  must recover without a human within one janitor interval. A drill that needs a human is a

  Trust and etiquette
  The threat is not a malicious teammate; it is a teammate's agent reading a hostile ticket,
  PR or skill and leaking that teammate's credentials or wrecking their machine. Fleet's
  README says it plainly: model-plane reads are unbounded. So every rule below is
  enforced by GitHub, the kernel or a hook, never by AGENTS.md .

  Enforced by GitHub

         main protected: required checks, merge queue only, no force push, no admin bypass,
        including for org owners.
        CODEOWNERS: factory/** , .adlc/** , .github/** , .claude/** need two human
        approvals. The settings that define quality are in that set: prosecuteFailOn , default -
        -max-strikes , quorum size, branch-protection rules as code, the quarantine list, the
        sandbox profiles. Lowering prosecution depth is a visible PR, never a config tweak.
        Node tokens are fine-grained, repo-scoped, branch-pattern-scoped ( ticket/** ,
         nodes/** , refs/locks/** ), 90-day expiry. Revoking a token retires a node.
        Secrets: none in the repo. CI has no model API key. Prosecution stays on nodes. Project
        secrets are per-node .env ; factory/fixtures/ holds synthetic data, and secret
        scanning treats fixtures as lookalikes.
        Labels are set only by write access. The claim filter is "label ready present", so nothing
        a stranger files becomes claimable without the desk. Only verifier-confirmed findings
        spawn fix tickets, never comments.
        Self-hosted runners on a public repo are the largest hole. w:heavy jobs run only on
         push events from branches matching ticket/** and never on pull_request from a
        fork; fork PRs get hosted runners only; "Require approval for first-time contributors" is
        on; runners live in a group scoped to this repo; no secrets on the runner host;
        ephemeral runners where the node can afford it.
        Human-authored PRs take the same gates and the same prosecution. No exemption.

  Enforced on the node

        vetto sandbox, fail-closed, two profiles (Repository and nodes). Ralon path lock on the
        rails. dcg (or Vallum) hook on every shell command. ACFS safe mode only.
        The wizard refuses to install if --dangerously-skip-permissions is aliased.
        Every node runs the same factory/policy/ set, pinned by factory/VERSION .

  Skills are untrusted input. Anything under factory/skills/ is text every node's agent
  will trust. skills-janitor /janitor-security runs in CI on every change to that directory
  and on each node before a skill loads; a RISK verdict blocks the merge. stalebrain and
   agentslint run weekly so a skill that describes a path or command that no longer exists
  is caught before an agent acts on it.

  Outbound etiquette. The factory's PRs will land in other people's repos eventually
  (upstream fixes, dependency patches). Before any PR leaves the project, the desk's
  policy check reads the target's AI-contribution policy from the melissawm index and
   good-oss-citizen 's reader: a ban is a hard stop; a disclosure requirement means the
   Assisted-by: trailer and a one-line note in the PR body. commit-check enforces the
  trailer in CI. Expect peakoss/anti-slop on the receiving end and write PRs that would
  pass it: small, one concern, tests included, no boilerplate prose.

  Humans erode rails before agents do. The 11pm "just this once" (hand-editing a flaky test
  on main , a temporary branch-protection exception) is the realistic threat, which is why
  admin bypass is off for everyone and the quality settings are code under CODEOWNERS.

  House rules ( factory/RULES.md , printed by the wizard):

        Agents sign every commit and PR with handle , ticket id, Assisted-by: and Signed-
        off-by: trailers.
        One ticket, one branch, one PR. Out-of-scope fixes become new desk requests, not
        drive-bys.
        Claims expire. Do not re-claim a ticket you just lost without reading its comments.
        Post your spend. The PR body carries strikes used and tokens if the adapter reports
        them. The number is for the group to see where quota goes, not a leaderboard.
        Bots do not open discussions, mention humans, or comment on each other's PRs.

        Taking your box offline for more than a day: run /factory:release first.

  Clock and janitor
  An hourly Action with a concurrency group, first-party because nothing published
  combines the three jobs. It owns every time-driven transition.

        Claims: delete lock refs whose commit is older than 24 h and whose ticket/<id>/*
        branch has no commit newer than the TTL; delete locks of stale nodes; delete a
        node's newest locks beyond its slots . Comment on the Issue each time, in dry-run
        form first for a week after any janitor change (the gemini-cli pattern).
        Branches: delete ticket/** branches whose Issue is closed, or unclaimed for 7 days
        with no open PR. crs-k/stale-branches is the fallback age-only sweep.
        Nodes: stale after 24 h silent, retired after 7 days; token revoked, claims released,
        manifest archived on the nodes branch.
        Previews: torn down at TTL or PR close.
        Ready queue: re-run merge-forecast when the open set changes; recompute ready
        labels.
        Drills: the monthly drill ticket (Humans in the loop).

  Must not: touch main outside the PR path, release a lock with a pushed branch newer
  than the TTL, run on a node, or overlap itself or the mirror job. Done when no state can be
  stuck for more than one janitor interval without a human noticing.


  Budget governor
  A check at the top of each loop, code only.

        Quota: cux pools the owner's accounts and reports window usage; the node sleeps
        when every account is at quota_cap (default 0.4) and resumes a strike mid-session
        when one rotates in. claude-usage-limiter 's hook is the per-project hard cap for
        nodes that run only Claude Code.
        Quiet hours: no claims inside the owner's declared window; a running strike finishes.
        Kill switch: factory/HALT present → sleep.
        Wall clock: fleet's --wall-clock-minutes from the ticket budget; the lock is kept and
        heartbeated across a pause.

  A paused ticket keeps its lock. Everything the governor does is a reason code in the
  ledger and a line in the digest.

  Distill loop
  P7 is a scheduled job on a volunteer factory-node runner, not something a node does
  after its own ticket. Every output lands on main through the same PR path as any ticket,
  with touches_factory true, and the RRSI discipline applies: a change to factory/ must
  pay for its added tokens with a measured gain on the calibration set, or it is reverted.

        Weekly lesson-foundry over factory/ledger/findings.jsonl : recurring verified
        findings become lint rules (PR'd with a test) or skill candidates. CauterRule 's replay
        validation is the second check: a candidate rule must also raise precision on the
        historical findings before promotion.
        Weekly skill rot: stalebrain (typed claim extraction, confidence half-lives) +
        agentslint (deterministic path/command integrity) + skillrot (CLI flag drift) over
        every SKILL.md and AGENTS.md ; stale claims open a needs-desk ticket.
        On a model release: model-ratchet re-prosecutes the hot paths of main with the
        new adapter; bug-bot --once is the alternative cron if model-ratchet is unavailable.
        Verified findings become tickets.
        Monthly calibration (Prosecution, verification, merge).
        Gate-manifest history feeds model-router priors so adapters are chosen per ticket
        category over time, not by feel.
         cass_memory_system mines node transcripts locally for dead-end rules; a node reads
        them before each strike. Rules that recur across nodes are promoted through lesson-
        foundry as text, never as transcripts.


  Observability
  Two numbers first: ready-queue depth (near zero means the desk is the limit, growing
  means nodes are) and acceptance-queue age (humans are). A static page on GitHub
  Pages, generated hourly by the janitor from the nodes branch, the lock refs, Issue labels
  and factory/ledger/ , in the issue-dashboard style: nodes online, claims held, queue
  depth by tier, acceptance age, spend by node for the week. No server, no login.

  The one open decision: the chassis. The spec assumes ADLC fleet composed by ru .
  The pass added two single-machine chassis that match the ticket → worktree → PR → CI-
  feedback loop with wider adapter support: Untrivial-ai/agent-orchestrator (mature, 20+
  harnesses, Go daemon) and Bernstein (deterministic gating, 31 adapters, one month old).
  Neither does multi-machine over a public repo; both would sit under this spec's claim
